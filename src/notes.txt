Implementation Notes
1) The Serializer, TextSerializer, and BinarySerializer took me quite a bit of time this week. My instinct was to use an abstract Serializer class with derived Text and Binary serialization classes, and this is how I ended up approaching the problem. In addition to the actual serialization classes, I define an abstract Serializable class (described below) and singleton SaveManager (for saving/loading binary game state data) and ConfigManager (for saving/loading user preferences in plaintext). 

2) The TextSerializer was actually pretty straightforward. I defined the recommended string utiltiies in the string_utils.hpp file, creating a new cge::utility namespace. Serialization for text files simply parses input documents and formats output documents with user-defined preferences. Currently, the ConfigManager handles screen resolution, game music, and test values but can be extended to support more configuration values. Note that if you modify the screen resolution, it works, but there's a glitch with the camera (it doesn't center on the player). I'll figure that one out as I push towards the final project deliverable.

3) The BinarySerializer is where I spent a majority of my time. In the end, I utilized the given templated functions as a starting point, which simplified things a bit. My BinarySerializer utilizes two primary data members: a vector representing a character buffer of raw data and a map of string keys to {offset, data_size} pairs. Raw binary data is stored within the character buffer, and the map can be used to get data from that buffer by providing an offset into the buffer and the size of the data stored at the offset. The binary save data always begins with an integer value representing the number of items within the file and is then composed of blocks of [key size, key value, data size, data value]. It looks something like:

    [Number of entries: int]
    [Key length: int]
    [Key string: char array]
    [Data size: size_t]
    [Data value: bytes]
    [Next entry...]

Endianness is handled by the given template functions. Currently, the game is loaded at the start of the program and saved at the end. I hope to soon add a menu where the user can save the game and also a key combination (CTRL+S) that the user can use to save in-game. 

4) To handle text and binary serialization, I define the ConfigManager and SaveManager classes. Configurations are plaintext user preference files and hold a TextSerializer object, and Saves represent game state and hold a BinarySerializer object. These classes are used to manage the overall configuration/save processes and are initialized in main. 

5) For serializing data within the program, I toyed around with the idea of using the visitor pattern, but I couldn't quite figure out how to make it work. In the end, I settled on a dedicated abstract Serializable class that classes can implement, which provides functions for serialization/deserialization. Admittedly, this complicates things a bit by adding a more complex inheritance structure, especially for nodes that then inherit from both the Node class and the Serializable class. Originally, I had TransformNodes inherit from Serializable, but I ended up just implementing it for my scene directly, which serializes node-specific data as needed.

6) Regarding the file system, I opted to use the resources directory for this project for simplicity but will try to find time to change this so that the solution is more consistent with normal standards.

7) Demonstrations for ints, floats, bools, and strings are included for both binary and text serialization. ConfigManager contains a function to increment a set of test values on each pass, and the main_scene does the same for test values for binary save data in the init() function. Note that I include config and save files in my resources directory, but these will be created automatically if they are not found on initialization.
